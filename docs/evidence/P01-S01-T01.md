## Canonical identity contract

Canonical document:

`docs/canonical/IDENTITY_AND_REVISION_MODEL.md`

Accepted decision:

`ADR-0038 — Canonical entity IDs are UUIDv7; revision and ordering are separate contracts`

The contract establishes:

- RFC 9562 UUIDv7 canonical IDs for the nine task entities;
- lowercase hyphenated canonical text;
- version 7, RFC variant, non-Nil, fail-closed validation;
- canonical IDs are opaque and non-secret;
- ID possession grants no authority;
- UUIDv7 creation time / lexical order is not freshness, causal, event, replay, retention, or security authority;
- positive uint32 revision domain `1..4294967295`;
- initial revision `1`;
- accepted revisioned mutation increments exactly one;
- expected-revision compare-and-swap;
- stale/zero/overflow writes fail closed;
- exact references bind ID plus revision for revisioned entities;
- ID-only/latest references are locator semantics rather than durable execution/evidence authority;
- provider/native IDs remain foreign metadata;
- Artifact logical identity is distinct from SHA-256 content identity;
- bytes cannot change under one Artifact ID;
- changed bytes require a new Artifact ID;
- reruns receive a new Run ID;
- AgentSession continuity is required to retain session identity;
- Runtime identity survives reconnect/restart only for the same enrolled trust identity.

## Mutability model

Revisioned:

- Project;
- Task;
- WorkUnit;
- Runtime;
- Artifact metadata.

Immutable identity records at semantic revision 1:

- Run;
- AgentSession;
- Evidence;
- Event.

Event and session live/current state remains projection/event state rather than mutation of the immutable identity record.

## Architecture consistency repair

The pre-existing architecture stated that durable Event IDs were “unique and monotonic within a run stream.”

That statement conflicted with the new identity rule because UUIDv7 lexical/time order must not become event-order authority.

The implementation corrected the architecture so:

- Event IDs are unique;
- later Event-envelope contracts own explicit stream ordering;
- UUIDv7 lexical order MUST NOT define event order.

The architecture also now distinguishes:

- immutable AgentSession identity from mutable projected usage/status;
- Artifact logical identity from content digest.
