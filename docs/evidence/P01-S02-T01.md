## Canonical contract

Primary document:

`docs/canonical/CAPABILITY_AND_GRANT_MODEL.md`

Accepted decision:

`ADR-0039 — Authorization uses exact actions, canonical resources, bounded Grants, and fail-closed intersection`

Important invariants:

- issued Grants bind one exact action;
- no action wildcard exists in an issued v1 Grant;
- unknown/unnegotiated action or extension denies;
- canonical authorization resources use `kernux://`;
- raw string-prefix resource authorization is forbidden;
- noncanonical/ambiguous encodings fail closed;
- URI parsing alone does not prove filesystem/network/browser safety;
- resource-kind-specific trusted resolvers own platform containment;
- consequence is kernel-owned and may be raised but not lowered by context;
- unknown/incomparable mandatory constraint denies;
- a Grant has exact subject/runtime/action and finite resource/time/use/delegation bounds;
- Grant widening requires a new authorization decision and new Grant ID;
- operation admission atomically consumes use budget;
- revocation/expiry/exhaustion deny new admissions;
- in-flight cancellation is deferred to S03;
- delegation requires independent C4 authority;
- child Grants can only narrow;
- child operations consume applicable ancestor budgets;
- UI profiles/persistent choices compile to policy, not wildcard bypass Grants;
- untrusted content cannot mint or widen authority;
- remote execution requires all mandatory policy/capability layers to allow.
