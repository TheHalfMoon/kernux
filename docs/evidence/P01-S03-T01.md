## Canonical runtime contract

Primary document:

`docs/canonical/RUNTIME_OPERATION_MODEL.md`

Accepted decision:

`ADR-0040 — Runtime truth uses negotiated capability, stable OperationId, host-owned observation, and reconcile-before-retry`

Key invariants:

- runtime/provider type never implies capability;
- capability advertisement never grants authority;
- contact and execution state are independent;
- disconnect/timeout/controller restart/heartbeat loss/cancel acceptance never prove exit;
- only authoritative execution-owner observation establishes host-owned terminal truth;
- RequestId and OperationId are distinct;
- one OperationId binds one canonical operation fingerprint;
- same OperationId + different fingerprint is conflict and does not execute;
- same OperationId + same fingerprint resolves one logical operation;
- ambiguous side-effect outcome retains/reconciles the original OperationId;
- automatic fresh-OperationId retry after `may_have_started` is forbidden;
- cancellation acceptance is not terminal execution proof;
- structured errors separate request failure from operation truth;
- unknown retry safety defaults to reconciliation;
- reconnect reauthenticates/renegotiates/reconciles and never resurrects expired authority;
- changed enrolled trust identity requires a different Runtime identity.
