## Core validator behavior

The qualified validator:

- bounds JSON input to 512 KiB;
- rejects manifest-file symlinks;
- rejects duplicate JSON keys;
- rejects non-finite JSON numbers;
- rejects malformed/non-UTF8 records;
- rejects unknown object fields through the strict v1 schema;
- rejects unsafe/non-canonical repository paths including traversal, absolute paths, Windows drive/ADS forms, backslashes, duplicate separators, dot segments, leading/trailing whitespace, and trailing slash aliases;
- preserves valid Unicode repository paths and internal spaces;
- rejects non-canonical or credential-bearing Git repository URLs;
- enforces exact Git versus artifact source identity;
- enforces prepared/imported lifecycle semantics;
- enforces transformation and generator semantics;
- rejects whitespace-only or padded provenance identity/reference text;
- validates local evidence as real non-symlink repository files;
- validates imported destination paths as existing non-symlink repository paths;
- validates import/adaptation commits as real repository commits and ancestors of validation HEAD;
- requires every import commit to actually touch every claimed non-reference destination;
- requires adaptation commits to strictly descend from the import commit and previous adaptation;
- rejects exact and directory/child destination ownership overlaps across provenance records;
- rejects hidden ledger state through symlink, nested-directory, or non-JSON entries;
- emits deterministic sorted diagnostics.
