The repository-owned `kernux-store` now proves:

- exact direct `sha2 0.11.0` with defaults disabled and no optional features;
- no new external package/version/source identity from direct sha2 admission;
- filesystem Artifact bytes remain physically separate from SQLite metadata;
- trusted caller-selected CAS root with no untrusted relative-path join API;
- deterministic `root/sha256/<first-two-hex>/<64-lowercase-hex-digest>` layout;
- fixed 64 KiB streaming buffer and explicit byte limit on every ingest/read;
- valid empty blobs and multi-chunk exact-boundary blobs;
- incremental SHA-256 computation using machine-computed bytes;
- optional expected-digest mismatch rejection before final publication;
- create-new temporary names and scoped cleanup on ordinary success/failure;
- temporary bytes are flushed and `sync_all` completes before final publication;
- final publication uses hard-link create semantics and never overwrites an existing final digest path;
- identical preexisting content is fully verified before success;
- corrupt preexisting final content fails without overwrite, repair, truncate, or quarantine;
- public results do not expose a dedup-hit flag;
- verified reads enforce an explicit bound, reject non-regular entries, hash the complete same file handle, compare the requested digest, rewind the same handle, then return it;
- missing, oversized, tampered, truncated, corrupt, and invalid-entry cases fail with typed generic errors;
- Unix symbolic-link CAS roots reject;
- binding re-verifies the exact blob from the same CAS before any SQLite mutation;
- Artifact binding requires exact expected revision and preserves existing `media_type` and `retention_ref`;
- existing digest/size invariants remain authoritative through the established metadata CAS;
- stale-revision and byte-identity conflicts leave the immutable published blob intact;
- two distinct logical Artifact IDs may bind one identical digest while keeping independent revisions/media/retention metadata;
- no final blob deletion, GC, retention execution, quota, export/import, policy evaluation, secret provider, KRP filesystem path, daemon state-root, runtime-host authority, or remote/cloud backend is introduced.
