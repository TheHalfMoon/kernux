## Notice validator behavior

The qualified validator:

- requires schema version integer `1`;
- rejects unknown or missing inventory fields;
- rejects malformed notice entry IDs and categories;
- supports exact Git and artifact source identities;
- rejects non-canonical, credential-bearing, query-bearing, traversal-like, or otherwise ambiguous Git repository URLs;
- requires full lowercase Git object IDs for Git source revisions;
- rejects duplicate entry IDs;
- rejects duplicate source identities;
- rejects duplicate license snapshot paths;
- enforces canonical repository-relative snapshot paths;
- rejects symlink traversal for snapshots and the license snapshot root;
- requires every referenced snapshot to resolve to a regular file;
- verifies SHA-256 byte integrity;
- rejects untracked files under the canonical license snapshot tree;
- reuses the strict provenance JSON reader, including duplicate-key, non-UTF8, non-finite-number, malformed, oversized, and symlink-input rejection;
- cross-checks tracked provenance records against notice source identity;
- requires provenance SPDX expression and upstream source-license path to match the notice inventory;
- requires provenance license evidence to include the preserved local snapshot;
- emits deterministic sorted diagnostics.

## Core hardening findings

Independent review and adversarial probes identified two real defects before the final core candidate:

1. Python equality allowed `schema_version=1.0` to compare equal to integer `1`;
2. an additional untracked license snapshot could exist under `third_party/notices/licenses/` without inventory coverage.

Both were fixed before final qualification and explicit negative probes confirmed the corrected fail-closed behavior.

Additional adversarial probes proved rejection of:

- unsafe repository URLs;
- duplicate source identities;
- unsafe snapshot paths;
- unknown properties;
- snapshot digest tampering;
- symlinked snapshots;
- provenance records without matching notice entries;
- provenance records omitting the required preserved snapshot.

- exact source identity and authorization;
- preserved license/notice evidence;
- embedded dependencies, assets, model/data artifacts, branding, executables, and hosted services;
- Kernux receiving boundary and exact source/destination mapping;
- transformation class;
- characterization before semantic adaptation;
- applicable security review;
- mechanical import/adaptation history;
- exact-head and post-merge verification.

It explicitly prohibits:

- importing first and reconstructing provenance later;
- treating an SPDX identifier as a substitute for preserved license text;
- treating founder permission as blanket permission for embedded third-party material;

- bypassing the notice inventory because release has not happened yet;
- weakening CI/Diffcipline/provenance validation to admit an import;
- treating the checklist itself or an agent self-report as import authorization/proof.
